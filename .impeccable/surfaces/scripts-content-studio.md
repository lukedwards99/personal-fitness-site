# Local content studio

Mode: Operate. Luke writes and uploads at his Mac, then chooses a hosted lane explicitly. This extends the existing content commands and established Split identity. The light writing canvas supports sustained editing in normal desk light. No new visual world or comp is required for this specific publishing tool.

## Direction contract

THESIS: A local writing workbench makes save and publication separate, visible actions. It avoids a dashboard of summary cards.

OWN-WORLD: Inter Tight, paper and graphite, restrained controls, and fine rules inherit the public site's language at an editor's fixed type scale.

STORY: Choose or create a journal entry or article, write, attach ordered media, preview, save locally, then publish the saved library to a named lane. R2 credentials stay on the server.

FIRST VIEWPORT: A compact title bar carries connection status. A narrow searchable library sits beside a generous labeled editor; save, preview, and a clearly targeted publishing control remain easy to locate. On phones the library and editor stack.

FORM: Direct authoring workbench extending the existing publishing workflow; no concept seed for this precisely scoped addition. Code build path. The signature interaction is the explicit transition from local saved writing to a verified lane release.

FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance

## Scope and constraints

Loopback only. Use the existing local R2 credentials. A temporary launch key protects each local session. No authored content, media, credentials, releases, or backups enter Git or public application bundles. Existing live site and content stay untouched while implementing and testing this PR. Test with an isolated external synthetic workspace.
